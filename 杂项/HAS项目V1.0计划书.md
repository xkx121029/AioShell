## 一、项目定义

### 1.1 一句话定位

AioShell 是一款安卓平台的开源第三方 AI 对话客户端外壳，**不内置任何大模型、不提供任何后端服务**，用户自行配置接口地址、密钥与模型参数，即可对接 AIO 系列、Ollama 以及所有兼容 OpenAI 协议的大模型服务。

### 1.2 核心判断

产品只做"交互层"，不做"模型层"。AI 能力完全由用户配置的第三方接口提供，客户端专注于连接、对话体验与本地数据管理。这一判断决定了本项目的所有功能边界、技术选型与合规策略：

- 做深：接口配置的灵活度、流式对话体验、本地数据安全
- 不做：模型服务、账号体系、云端同步、广告、用户数据采集

### 1.3 目标用户

| 类型 | 特征 | 诉求 |
|------|------|------|
| 技术爱好者 | 懂 API 地址、密钥、模型参数 | 自由切换模型、私有化 |
| 开发者 | 自建推理服务、二次开发 | 可控、可扩展、开源 |
| 本地模型部署用户 | 使用 Ollama、自建服务 | 手机端接入自己的模型 |
| API 接口使用者 | 持有合法第三方接口权限 | 稳定、轻量的对话工具 |

**非目标用户**：完全不懂接口配置的纯小白。产品不做"开箱即用"式教育引导，避免牺牲"自由、无绑定"的核心理念。

### 1.4 竞品差异

| 维度 | 豆包 / 通义千问 | AioShell |
|------|----------------|----------|
| 模型能力 | 内置、一体 | 不内置，用户自配 |
| 后端服务 | 官方提供 | 无，用户自行提供 |
| 数据存储 | 云端为主 | 纯本地 |
| 绑定关系 | 强绑定官方模型 | 无绑定，自由切换 |
| 商业化 | 广告 / 增值 | 免费开源、无广告 |

## 二、V1.0 产品范围

### 2.1 版本目标

V1.0 的验收标准：**用户拿到 APK 后，能够自行配置一个兼容 OpenAI 协议的接口，完成多会话、流式对话，且对话数据仅保存在本机。**

### 2.2 功能清单（V1.0）

**A. 接口配置模块**

- A1. 自定义 API 地址（Base URL）
- A2. 自定义访问密钥（API Key）
- A3. 自定义模型名称
- A4. 参数调节：temperature、max_tokens、top_p
- A5. 连接测试（验证配置可用性）
- A6. 多接口配置档案的保存与切换

**B. 会话管理模块**

- B1. 多会话创建
- B2. 会话切换
- B3. 会话重命名
- B4. 会话删除
- B5. 历史会话本地持久化存储

**C. 对话交互模块**

- C1. 上下文记忆（携带历史消息）
- C2. 流式输出（SSE 打字机效果）
- C3. 复制回复内容
- C4. 错误提示与重试

**D. 数据与安全模块**

- D1. API Key 本地加密存储
- D2. 会话数据本地存储（不上传第三方）
- D3. 无广告、无后台联网采集

**E. 体验模块**

- E1. 轻量化启动
- E2. 深色模式（基础支持）

### 2.3 明确不做（V1.0 排除项）

以下功能在 V1.0 明确排除，放入后续版本评估：

- 账号体系与云端同步
- 多轮图片 / 语音 / 多模态输入
- 插件化 / 脚本系统
- 会话数据导出为 Markdown（移至 V1.1）
- 更多协议适配（如 Anthropic 等，V1.0 仅覆盖 OpenAI 兼容协议）

## 三、技术架构

### 3.1 技术选型

| 模块 | 选型 | 理由 |
|------|------|------|
| 开发语言 | Kotlin | Android 现代开发标准 |
| UI 框架 | Jetpack Compose | 声明式 UI，开发效率高 |
| 架构模式 | MVVM + Repository | 分层清晰、易测试 |
| 网络层 | OkHttp + Retrofit / Ktor | 兼容 OpenAI 协议与 SSE |
| 异步 | Kotlin Coroutines + Flow | 适配流式输出 |
| 本地存储 | Room + DataStore | 会话 + 配置 |
| 密钥安全 | Android Keystore + EncryptedSharedPreferences | 加密保存 API Key |
| 依赖注入 | Hilt | 降低耦合 |

### 3.2 关键架构设计

**1. 网络适配层（核心）**

抽象统一的 `OpenAICompatibleAdapter`，定义标准请求/响应结构。后续扩展其他协议格式时，只需新增适配器，不改动业务层。

```
网络层结构：
├── ApiClient（统一入口，负责鉴权与请求构建）
├── OpenAIChatAdapter（实现 chat/completions 协议）
├── StreamParser（SSE 流式解析）
└── ErrorMapper（错误码映射）
```

**2. 流式输出设计**

流式输出采用 SSE（text/event-stream），逐块解析 `data:` 字段并更新 UI。配合 Flow 的冷流特性，实现流畅的打字机效果，并支持中途停止生成。

**3. 数据分层**

```
数据层结构：
├── ConfigRepository（接口配置，DataStore + 加密存储）
├── SessionRepository（会话，Room）
├── MessageRepository（消息，Room）
└── ChatRepository（编排配置 + 会话 + 网络请求）
```

### 3.3 项目模块划分

| 模块 | 职责 |
|------|------|
| app | 应用入口、依赖装配 |
| core:network | 网络请求、SSE、适配器 |
| core:database | Room 实体、DAO、数据库 |
| core:security | 密钥加密、安全存储 |
| feature:config | 接口配置 UI 与逻辑 |
| feature:chat | 对话 UI 与逻辑 |
| feature:session | 会话列表 UI 与逻辑 |
